CHAMFER DIRECTION RESEARCH PIPELINE
===================================

Purpose and current status
--------------------------
This research asks whether global correspondence can propose useful deformation
directions that Chamfer-based optimization does not discover, and whether a neural
deformation model can realize those directions. The current implementation is a
mechanism study, not an established improvement over the baseline. No candidate
has passed all adoption gates. The default optimizer remains Chamfer + Adam.

The direction study replays six development pairs at nine states per pair, giving
54 correlated states, not 54 independent scenes. It compares geometric and FPFH
transport fields, parameter gradient descent, ridge lifting, and actual Adam.
The time-matched continuation audit is complete: all 54 starts still improve
under Adam continuation. No OT-ridge candidate beats the best within-budget Adam
Chamfer value in this audit. Some candidates improve GT error more than Adam,
but that does not establish overall superiority or pass the existing gates.
The subsequent mass-weighted displacement study also passes its numerical checks
but fails adoption. Better alignment to a proposed displacement is insufficient
to establish better registration. It reuses the same development states.
Removing the spatial matching term also fails adoption. None of these controls
has established an improvement suitable for replacing the baseline optimizer.
The observable-selection screen also fails all adoption gates. Its cap-1 trials
reduce Chamfer in every state but do not establish additional GT improvements
over choosing between GD and Adam. These are reused development records.
The baseline stopping audit also fails to establish stagnation: all 54 original
level endpoints and all 54 capped-500 endpoints admit more than 0.1% best-observed
CD improvement within 100 further Adam updates at the existing learning rate.
At 33 of the 54 original endpoints, final CD decreases while GT MSE increases.
These findings support separating objective mismatch from optimizer stagnation;
they do not establish a successful remedy or a new independent-scene result.
In the budget-only control with fresh stage handoffs, increasing 50 to 500
updates per level lowers sampled training CD but raises full-cloud EPE on all
six reused pairs. Longer optimization alone does not fix the observed mismatch.
The observed-spacing field comparison and exact-kernel follow-up also fail their
frozen screens. Twelve exact replays compare CD, robust NN, centroid, MMD and UOT
at all 54 original stage endpoints. This is another mechanism result, not an
adopted replacement for the optimizer or an independent-scene evaluation.

Architecture
------------
Observed source X and target Y
        |
        v
NDP baseline: 9 deformation levels x 50 Adam updates
        |
        +--> final registration --> independent GT evaluation
        |
        +--> clone states at levels {0,4,8}, updates {0,25,49}
                  |
                  v
          global correspondence plan P
          geometric cost / frozen FPFH feature penalty
                  |
                  v
          point force f = P Y - diag(P 1) Z
                  |
                  +--> GD: delta_theta = J^T f
                  |
                  +--> ridge: (J J^T + gamma I) a = f
                              delta_theta = J^T a
                  |
                  +--> weighted: (J^T R J + gamma I) delta_theta = J^T f
                                 R = diag(P 1), matrix-free solve
                  |
                  v
          normalize predicted output speed to the actual Adam update
                  |
                  v
          backtracking: objective decrease + output linearization agreement
                  |
                  v
          evaluate actual output, Chamfer change, and GT risk change

Z denotes the current warped source and J = dZ/dtheta for the active NDP level.
Every diagnostic trial changes a clone. The original baseline trajectory and its
Adam moments remain intact; recorded endpoints and traces must replay exactly.

Baseline and objective
----------------------
The baseline uses symmetric UNSQUARED Euclidean Chamfer:

  CD(Z,Y) = mean_i min_j ||z_i-y_j|| + mean_j min_i ||z_i-y_j||.

The source and target are separately centered, matching the historical baseline.
Each uses at most 2,000 sampled points. The fixed-budget loop makes 50 updates
and an endpoint evaluation at each of nine levels. Each level has its own Adam
optimizer (learning rate 0.01). The model uses three hidden layers of width 128,
frequency start k0=-8, and axis-angle SE(3) motion. Baseline parameters are float32;
cloned direction calculations use float64. The frozen reference test checks the
loop against its pre-refactor implementation, including RNG state and losses.
The original NDP configuration permits up to 500 iterations with early stopping.
Our fixed 50-update loop is a controlled budget adaptation, not reproduction of
the complete published benchmark or a collection of converged NDP optima.

A separate baseline-only stopping audit uses the original 500-iteration ceiling
and original stopping logic. Its small-change counter accumulates 15 events;
the events need not be consecutive. A second arm disables only those stopping
checks and runs the full ceiling, preserving the original cached stage handoff.
A third arm uses the existing fixed-budget loop at 500 updates, evaluating a
fresh endpoint before stage handoff. This isolates the larger update budget
from the original capped loop's use of a cached pre-update output.
At every level endpoint, two independent clones continue Adam for 100 updates
with the existing moment history and learning-rate multipliers 1 and 0.1.
Neither path uses GT to choose its updates or termination. Reports separate
best-observed CD progress, final CD progress and GT error. A finite continuation
test does not certify stationarity, a local minimum, or global convergence.
The instrumented original runs must exactly match uninstrumented references.
Their elapsed times include observation overhead and are not runtime benchmarks.
This audit reuses six development pairs; it does not replace earlier failed
adoption gates or evaluate a new registration method.

Proposal, transfer, and acceptance
---------------------------------
pipeline/capacity.py implements soft, semi-relaxed, unbalanced, and balanced
entropic transport. Costs are half squared Euclidean distances. The geometric
scale sets epsilon; the relaxed marginal penalty uses tau=2*epsilon. Scaling
residuals must pass the numerical gate; balanced transport can use damped Newton
refinement when requested with --newton.

pipeline/features.py computes normalized, 33-dimensional FPFH descriptors from
the observed current source and target. Let h be their pooled mean nearest-
neighbor spacing. Normal estimation uses radius 2h and at most 30 neighbors;
FPFH uses radius 5h and at most 100 neighbors. The cost adds epsilon times
0.5*||descriptor_i-descriptor_j||^2/0.1^2. Features and epsilon are frozen for
each trial. This is not differentiation through the feature extractor and is
not a full implementation of RobOT.

Distinguish row mass r_i=(P1)_i, barycentric displacement
v_i=(P Y)_i/r_i-z_i when r_i>0, and force f_i=r_i*v_i. The force-ridge control
fits FORCE with unweighted regularized least squares:

  min_delta 0.5*||J delta - f||^2 + 0.5*gamma*||delta||^2.

It does not solve a mass-weighted barycentric displacement fit. Gamma is 0.01
times an eight-step power estimate of the largest eigenvalue of J J^T. The
matrix-free conjugate-gradient solver reports its actual residual. Raw residual,
direction agreement, damping shrinkage, and post-normalization residual are
different quantities. The dedicated audit records each separately. Its ridge
force-fit median residuals remain about 0.97-0.99 even after positive rescaling;
this is not, by itself, proof of an unrepresentable target direction.

The weighted control instead solves
  min_delta 0.5*||sqrt(R)*(J delta - v)||^2 + 0.5*gamma*||delta||^2.
It reuses the same solver with weighted Jacobian sqrt(R)*J and target
f/sqrt(r), setting the target to zero at zero-mass rows. Its damping uses the
same recipe on the weighted kernel. This is standard weighted least squares,
not a new optimizer. Correspondence-weighted displacement fitting is already
present in RobOT, NeurIPS 2021, Eq. (8): https://arxiv.org/abs/2111.00648 .
Transport row masses are not assumed to be calibrated correspondence confidence.

For a nonzero exact weighted solution, the frozen surrogate's initial slope is
  -f^T J delta = -||sqrt(R)*J delta||^2 - gamma*||delta||^2 < 0.
This proves surrogate descent, not uniform GT-risk descent. Even an ideal target
v=-e can hurt uniform risk: for scalar parameter J=(1,2)^T, e=(3,-1)^T,
R=diag(0.01,1), delta=1.97/(4.01+gamma)>0, the uniform MSE derivative equals
delta>0. Tests cover this counterexample, the dense normal-equation solution,
uniform-mass direction equivalence, and global mass-scaling invariance.

For a frozen plan, displacement d=Z_trial-Z has surrogate change

  Q(d)-Q(0) = 0.5*sum_i r_i*||d_i||^2 - sum_i f_i dot d_i.

The primary transport controller tests this surrogate. A separate common-CD
controller tests Chamfer directly; raw finite steps are diagnostic controls.
Backtracking requires Armijo decrease (coefficient 0.1) and relative output
linearization error <=0.1, with up to 21 dyadic attempts and caps 1/16, 1/4, 1.
The surrogate controller does not guarantee a decrease in Chamfer or GT error.
The actual nonlinear output is always evaluated. This is a local frozen-plan
argument, not a global convergence theorem for adaptive features or epsilon.

Evaluation and attribution
--------------------------
Observed target Y is an input to matching and optimization. GT is the separately
known position of each source point after the true deformation. The 4DMatch
loader reconstructs it from flow, rotation, and translation; the prepared HF
3DMatch experiment uses real fragments with a controlled 30-degree source
rotation and a translation of 0.1 source radius. Its stored truth is the original
source fragment before this perturbation, not official pose-benchmark ground
truth. The loader applies the stored normalization scale. GT is used only
for evaluation, risk derivatives, and offline development gates. It is absent
from transport, ridge lifting, and the step controller. Development choices have
used these evaluations, so these pairs are not an untouched test set.

Reports verify complete state/method/policy grids, solver convergence, exact
baseline replays, and the identity
  MSE(Z+d)-MSE(Z) = 2*<Z-GT,d>/N + ||d||^2/N.
They compare GD and ridge on the same field to isolate transfer, and compare
feature fields with geometric fields having the SAME marginal model. Adoption
requires both data families to pass the frozen local and finite-step gates.
Zero/rejected updates are not rescues. Only passing candidates may proceed to
new native training trajectories and independent scenes. Current feature
candidates do not qualify. Neither conference acceptance nor general superiority
has been established.

Time-matched continuation audit
------------------------------
ndp_budget_probe.py clones each native model and its pre-update Adam moments.
Recomputed first updates must exactly match the original native update. Each
proposal pays for its Adam speed calibration, model/Jacobian setup, matching,
transfer, normalization and native finite controller. Trial parameters are
rounded to float32 and evaluated in the native model. GT diagnostics and record
writing are excluded from both computation budgets.

Two Adam timing repetitions continue the same active level, inputs and optimizer
history. This is a local continuation, not the original later-level schedule.
The main comparison gives Adam its lowest observed CD through the first evaluated
state after the time deadline. A sensitivity check uses only evaluations strictly
within the budget. Neither selection uses GT. The study recorded 1,080 native
trials and 5,432 Adam evaluation states. Budgets were 0.040-0.442 seconds on the
measured device; Adam reached 5-68 updates at the first post-budget evaluation.
These timings are not universal hardware-independent compute claims.

No plateau was observed at relative-gain thresholds 1e-6, 1e-4 or 1e-3. The
smallest strictly within-budget Adam CD gain across comparisons was 0.001231.
No OT-ridge method beat its matched Adam comparator in both repetitions, with
either controller. At a differentiable state, an exactly zero parameter gradient
also rules out negative first derivatives in every parameter direction; finite
assignment-boundary crossings and algorithmic stagnation are distinct questions.

The current speed normalization has an explicit limitation: if the actual Adam
output speed is zero, every scaled proposal is also zero. Thus this pipeline
cannot presently claim escape from exact Adam stagnation. A useful raw direction
and a nonzero accepted normalized update are different requirements.

Weighted displacement control
-----------------------------
ndp_weighted_probe.py keeps the same matching fields, sampled states, speed scale,
step caps, controllers, and adoption gates. Each field compares GD, force ridge,
and mass-weighted fitting. All six baseline endpoints/traces replay exactly;
old control and force-transfer measurements match the preceding audits exactly.
The report checks 756 directions, 6,804 finite trials, 432 ridge solves, and
648 transfer measurements. Weighted fitting lowers the median weighted ray error
in all eight field/family groups, but every candidate still fails the original
adoption gates. No weighted candidate has proceeded to a native training run or
new scene. Its time-matched Adam comparison is therefore not yet performed.

Feature-only correspondence control
----------------------------------
ndp_descriptor_probe.py compares the preceding mixed cost with feature-only
matching. In dimensionless units, the mixed cost is C/epsilon+B; the control
removes C/epsilon and uses B alone with entropy 1 and relaxed marginal penalty 2.
It preserves the descriptors, transfer operators, speed scale and adoption gates.
For frozen descriptors, feature-only OT is spatially constant: its displacement
force comes from the separate Q fitting objective, not its spatial derivative.

For soft matching, a correct feature margin G and spatial disadvantage A give
pairwise correspondence odds exp(G-A); removing the spatial term gives exp(G).
This conditional benefit has an opposite limit: indistinguishable descriptors
can pull an already correct shape toward its centroid. Neither dominance nor
correct FPFH correspondence is guaranteed. RobOT already uses feature matching
and spatial fitting; this experiment is a mechanism control.

The six exact replays again cover 756 directions and 6,804 finite trials, with
all preceding mixed controls matching exactly. Every feature-only candidate
fails adoption. In HF, feature-only soft matching improves point-field alignment
from 4/18 to 7/18 states, but weighted parameter transfer loses three favorable
directions and achieves finite GT descent in only 4/18 states. Both matching and
transfer remain limitations. Reports split these effects by deformation level.

Observable selection control
----------------------------
pipeline/selection.py takes only method name, CD slope/change, trial acceptance,
output linearization error and weighted ray residual. It rejects extra fields.
The adapter discards GT and state identifiers from existing evaluation records.
The three fixed rules choose the smallest CD slope, the smallest eligible finite
CD change, or the smallest ray residual among eligible global proposals. Finite
eligibility requires an accepted cap-1 Q/CD-baseline trial, linearization error
at most 0.1 and negative CD change. Baselines or identity provide fallbacks.

selection_report.py merges verified weighted/descriptor records: 18 global
directions plus GD and Adam at each of the same 54 states. It saves each choice
before evaluating GT outcomes, and reuses that direction at every smaller cap.
Baseline-only selectors and the fixed feature_soft_weighted proposal test
whether the global library contributes anything beyond optimizer selection.
All three rules fail the unchanged gates. This retrospective screen does not
charge computation or validate a native online selector. A successful future
selector must pay for every proposal, solve and trial, including rejected ones.

Damping-path control
--------------------
ndp_damping_probe.py fixes the feature_soft and descriptor_soft proposals and
varies mass-weighted ridge damping at ratios 1e-2, 1e-3, 1e-4 and 1e-5 to the
same seeded power estimate. It records raw fit/ray residuals and parameter norms
before the unchanged Adam-speed normalization and finite-step tests. The 1e-2
control must reproduce the previous weighted results within 1e-8.

For A=sqrt(R)J and b=R^(-1/2)f, each positive eigenvalue mu of AA^T filters b by
mu/(mu+gamma). Lowering gamma reduces raw and weighted ray residuals while
increasing parameter norm. A remaining finite-gamma residual only upper-bounds
the component outside range(A); it does not prove a tangent-space obstruction.
Solver residuals bound output error and distinguish actual fit improvements
from incomplete solves. Neither a lower fit residual nor Q descent guarantees
better GT alignment or finite nonlinear behavior.

The initial 512-iteration path stopped on an unconverged solve. --accurate reruns
the same complete comparison in precision/ with 2048 CG iterations and the same
1e-8 residual tolerance. Historical callers retain the original 128-iteration
default. Failed partial outputs remain available; they are not merged into the
complete comparison. No outcome-based damping selection is implemented.

The complete rerun reproduces all six baseline traces and the 1e-2 controls
exactly. All 432 solves pass (maximum 877 iterations). Lower damping reduces
transfer error but every candidate fails adoption. In HF, the mixed field's
median raw weighted error falls from 0.940 to 0.757, while finite GT-descent states
fall from 9/18 to 5/18. Raw parameter norms grow and accepted fractions shrink.
The feature-only field also fits better but stays at 4/18 finite GT descents.
These outcomes do not establish a new optimizer or a range obstruction.

Observed-spacing field comparison
---------------------------------
ndp_field_probe.py clones all nine original stopping endpoints on each reused
pair. It compares symmetric Euclidean CD; saturating NN phi(d)=s(1-exp(-d/s)),
s=4h; squared centroid distance; Gaussian RFF-MMD at bandwidths 4h and r; and
geometric unbalanced OT. Here h is pooled within-cloud mean nearest-neighbor
spacing and r is mean RMS radius. Robust NN is continuous but still nonsmooth
at NN ties; it is not OAR. The MMD controls are not the complete MMD-Reg method.
RFF uses 512 paired sine/cosine frequencies with a local, fixed random generator.

Every field uses GD and ridge, with the same seeded spectral damping ratio .01,
CG tolerance 1e-8 and ceiling 2048. All directions, including the cloned Adam
direction, have linearized RMS motion h. Zero directions stay zero. This removes
the earlier dependence on Adam speed. Raw, own-objective trust and common-CD
trust are tested at caps 1/16, 1/4 and 1. The OT controller uses frozen-plan Q;
the others use their actual frozen-scale objectives. GT evaluates effects only.
The original native baseline endpoint and trace must remain exactly identical.

The primary arm has 324 converged solves, 702 directions and 6,318 finite trials.
The local RFF gradient has median cosine .828 with exact Gaussian MMD. Therefore
ndp_exact_field_probe.py repeats both MMD bandwidths with exact kernels, without
changing scales, transfer, motion bounds or gates. All 216 non-MMD field records,
216 non-MMD solves, 486 control directions and 4,374 control trials match exactly.
Exact kernels have quadratic pairwise cost; no linear-runtime claim is inherited.

All fields fail the strict screen in both runs. At the 36 4DMatch endpoints,
the UOT point direction is task-favorable in 33 states, but ridge turns 19 of
those into task-adverse directions. CD itself has 32 favorable point directions;
GD loses 16 and ridge loses five. In the 18 HF endpoints, the large-bandwidth MMD
point field is task-adverse everywhere with either estimator. This separates a
proposal problem from a transfer problem; neither is solved by a lower surrogate
loss alone. These are stage-level counts from six pairs, not independent samples.

fields_report.py checks the complete grids, actual solver residuals, normalized
motion, Armijo/linearization conditions and exact MSE-change identity. It records
lost point descents and a GT-conditional ray-alignment sufficient condition.
The latter is an offline explanation, not a deployable GT-free certificate.
exact_fields_report.py additionally verifies unchanged controls and estimator
effects. Earlier failed adoption gates remain intact; no native candidate or
new-scene evaluation has been justified by this field comparison.

field_selection_report.py then applies the existing CD-slope, CD-trial and
eligible-ray rules to the exact-field records. It compares NN-only, NN plus
centroid, and full libraries, saving 486 choices before GT scoring. The selector
receives no GT or state identity; CD-ridge joins GD/Adam as a declared baseline.
Historical callers retain their previous default baseline set. All three rules
fail the frozen screen, including attribution against the same rule without
MMD/OT. This is retrospective development analysis, not a new native algorithm.
The GT-only finite oracle covers 29/36 4D states with NN directions and 36/36
after adding only centroid directions; adding MMD/OT does not increase that
coverage. In HF it changes 14/18 to 15/18. Oracle magnitudes can still differ;
these counts neither establish a deployable selector nor a universal upper bound.
Ideal point transfer also fails to make any fixed non-CD field beat equally
ideal CD in both families. Better fitting alone is therefore not a demonstrated
remedy for this fixed field library.

Small root modules preserve historical imports used by tests and experiments.
The publication includes their dependency closure, not obsolete source backups,
experiment outputs, datasets, checkpoints, or caches. Each source file has fewer
than 500 lines. This document is the only newly added research documentation.

Setup and execution (from this document's directory)
----------------------------------------------------
Use an existing compatible Python environment. Install the appropriate PyTorch
build for your hardware, then the packages in requirements.txt. Keep temporary
files and caches inside this lab. For example, in a Linux shell:

  mkdir -p cache/matplotlib tmp paper_revision
  export PYTHONDONTWRITEBYTECODE=1 PYTEST_DISABLE_PLUGIN_AUTOLOAD=1
  export MPLCONFIGDIR="$PWD/cache/matplotlib" TMPDIR="$PWD/tmp"
  export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
  python scripts/fetch_ndp.py
  python -m pytest -q

The source fetcher checks SHA256 digests of upstream NDP files at commit
63e9e2767e3db96a12bae18146971adeddcb9a4e of
https://github.com/rabbityl/DeformationPyramid . It retains the required AST
definitions without changing their function/class logic. Upstream code remains
subject to its original license. The downloaded definitions are not committed.
It also fetches the historical InfoCD and Density-aware Chamfer Distance control
functions at the commit hashes embedded in the script, checking their SHA256
digests. Existing matching definitions are retained; different files are never
overwritten. On a server without Internet access, run the fetcher on a connected
machine and copy only the resulting assets/*_official directories into this lab.

Dataset-free CPU tests need these downloaded model definitions and Open3D.
GPU/data replay tests skip when their required resources are unavailable; skips
are not validation of full experiment reproduction. The benchmark data is not
redistributed here. Place previously prepared files at:
  assets/4dmatch_replication/{100,101,124,125}.npz
  assets/hf_3dmatch/{200,201}.npz
4DMatch arrays: s_pc, t_pc, s2t_flow, rot, trans, correspondences.
HF arrays: source, target, truth, overlap, scale.
Use the existing dataset permissions and the original preparation/normalization;
an arbitrary NPZ with these field names does not reproduce the recorded study.

With those assets and an idle allocated CUDA GPU:
  export CUDA_VISIBLE_DEVICES=<allocated GPU index> CUDA_CACHE_DISABLE=1
  python scripts/baseline.py
  python ndp_capacity_probe.py --newton
  python capacity_report.py
  python ndp_feature_probe.py
  python feature_report.py
  python ndp_budget_probe.py
  python budget_report.py
  python ndp_weighted_probe.py
  python weighted_report.py
  python ndp_descriptor_probe.py
  python descriptor_report.py
  mkdir -p paper_revision/selection_20261018 paper_revision/damping_20261018
  python selection_report.py
  python ndp_damping_probe.py --accurate
  python damping_report.py
  mkdir -p paper_revision/stopping_20261018
  python ndp_stopping_probe.py
  python ndp_stopping_handoff.py
  python stopping_report.py
  mkdir -p paper_revision/fields_20261018
  python ndp_field_probe.py

The feature report requires the preceding capacity controls; the weighted report
also checks the preceding feature and budget controls. The descriptor report
checks the weighted study's mixed controls. Selection uses weighted and descriptor
records; the damping report checks its 1e-2 controls against descriptor records.
Existing reference
results may be supplied instead of regenerating baselines. Reports consume local
TXT/JSON records and produce tables and PNG figures; none are bundled in Git.
Each pre-fit storage check requires the lab below 800 MB, with a total working
folder limit of 1 GB. Run directories are never silently reused.
