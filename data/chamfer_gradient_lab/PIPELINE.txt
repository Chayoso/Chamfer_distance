CHAMFER DIRECTION RESEARCH PIPELINE

Purpose and current scope
Study where a global correspondence direction loses usefulness: its point field,
its transfer through a neural deformation model, observed-loss mixing, or actual
nonlinear application. Chamfer + Adam remains the baseline. No candidate has
passed the complete adoption protocol. The latest normalization-aware mixture
is a local screen candidate, not an adopted full registration pipeline.

Data flow
 Observed source X and target Y
   -> NDP state and its own Adam history
   -> observed global correspondence / point displacement proposal
   -> regularized neural parameter transfer using JVP/VJP
   -> output-motion normalization and observed-CD direction mixing
   -> native float32 backtracking and motion-consistency check
   -> commit update
   -> evaluate with GT, without feeding GT back into the decision.

Optimization and evaluation data
The observed target cloud is available to optimization. Evaluation GT is the true
position of each source point; it never chooses a proposal, ridge, beta, step or
Adam checkpoint. GT is used for offline research screening, so repeatedly used
development examples are not an untouched validation set.
4DMatch uses flow, rotation and translation to reconstruct GT. The HF-derived
3DMatch data use real fragments with controlled 30-degree rotation and translation
of 0.1 source radius. That synthetic perturbation GT is not the official pose
benchmark's ground truth. Preserve the prepared normalization and point IDs.

Native baseline
The observed loss is symmetric UNSQUARED Euclidean Chamfer:
 C(Z,Y)=mean_i min_j ||z_i-y_j|| + mean_j min_i ||z_i-y_j||.
Each cloud is centered separately; at most 2,000 points are sampled. NDP uses
nine levels, depth 3, width 128, initial frequency k0=-8, axis-angle SE(3) motion
and per-level Adam with learning rate .01. Native parameters are float32;
direction calculations on cloned models use float64.
The original loop allows 500 iterations and an accumulating 15-event small-change
counter. Fixed-budget experiments instead use fresh stage endpoints and declared
budgets such as 50 updates per level. These are separate baseline definitions.
Exact replay excludes elapsed time and requires the original environment/data.

Current global proposal and neural transfer
FGR uses observed source/target geometry and FPFH descriptors. Its transform is
applied to ORIGINAL sampled source points, then expressed relative to the target
mean. The fixed anchor A therefore does not follow the current deformation Z.
The proposed field is f=A-Z. No GT correspondence is used to construct A.
With J=dZ/dtheta, GD gives delta=J^T f; full ridge gives
 delta=J^T (J J^T + gamma I)^(-1) f.
The current PCG candidate solves that same full system. An affine translation-
head preconditioner accelerates a solve; it does not restrict the parameter
space or change the exact ridge solution. Standard numerical linear algebra
and scalar mixing alone are not claimed as novel methods.
The current ridge ratio is 1e-4 times an eight-step seeded kernel power estimate.
Use seed 93000+100*pair+level, at most 2,048 CG iterations and actual relative
residual <=1e-8. Preserve historical controls' own declared settings.

Output normalization and direction mixing
Normalize each nonzero neural velocity J delta to norm B=sqrt(n)*h, where h is
pooled within-cloud mean nearest-neighbor spacing. A zero direction stays zero.
Let a be the normalized PCG ray, c the normalized CD-GD ray, and g the observed
output gradient. Write sa=g.a and sc=g.c<0. The original mixture has
 beta0=0 if sa<=.5*sc, otherwise (sa-.5*sc)/(sa-sc).
Combine parameter rays and normalize their recomputed JVP to B. This guarantees
the half-reference observed slope in exact arithmetic; it is not a GT guarantee.
The optional fgr_normmix rule accounts for normalization when choosing beta.
With rho=(a.c)/B^2, it finds the minimum beta in[0,beta0] satisfying
 ((1-beta)sa+beta*sc)/sqrt((1-2*beta)^2+2*(1+rho)*beta*(1-beta)) <= .5*sc.
It uses 64 scalar bisections and retains the feasible endpoint. Nearly parallel
or antipodal rays, |rho|>=1-1e-12, retain beta0. Invalid geometry and non-descent
references fail explicitly. The recomputed JVP is checked numerically.
Only the scalar rule changes; anchor, PCG, CD reference and controller are shared.
pipeline/native_mix.py exposes the candidate; trajectory_mix.py can apply it
within a declared own-history research trajectory. This is not adoption.

Native acceptance and optimizer state
Evaluate actual float32 parameters/output, not only the linear prediction.
For each declared cap, halve at most 20 times and require observed-CD Armijo
coefficient .1 plus relative output linearization error <=.1. Screens use caps
1/16,1/4,1; production-style replacement uses cap1. Preserve rejected steps.
In diagnostic clones, the original parameters and Adam moments remain intact.
In trajectory replacements, first advance the actual Adam moments, restore the
parameters, and apply the accepted alternative. Rejection keeps the advanced
moments. A fresh post-update forward feeds the next stage. Moments restart per
stage. The default event is the final stage update; denser schedules must be
explicit. Errors preserve their record and stop; no silent alternative direction.

Controls and interpretation
Historical controls include CD-GD, ridge, Adam, soft/balanced/semi-relaxed/
unbalanced transport, centroid, saturating NN, feature fields and Gaussian MMD.
For transport pi, row mass r_i=sum_j pi_ij and force
 f_i=sum_j pi_ij*(y_j-z_i) differ from barycentric displacement f_i/r_i.
Zero-mass rows have zero force. Weighted displacement fitting and its mass
weights are standard least squares, not calibrated matching confidence.
These are controlled components, not full reproductions of RobOT, OAR or MMD-Reg.
An exact ridge solve can lose task alignment, and valid CD mixing can reject a
task-helpful direction. Lower CD does not certify lower correspondence error.
All original stopping endpoints admit further CD improvement under continuation;
the current evidence does not establish escape from a local minimum.

Observation and advancement
The baseline screen uses 6 reused pairs x 9 original endpoints =54 correlated
states. The separate own-history event audit uses 108 corrections from six paths;
its states are not interchangeable with the original54. GT observers run after
proposal/application and are regression-tested for unchanged outputs and RNG.
For task MSE R, actual motion D obeys
 R(Z+D)-R(Z)=2<Z-T,D>/n+||D||^2/n.
Report finite identities, true solver residuals, actual/native motion, both task-
gradient precisions, rejection counts, full sign chains and pair-level magnitudes.
A first failing stage is an accounting label, not a unique causal attribution.
The strict absolute 1e-12 identity checks and original decision grids remain.
The latest local gate has 40 cells across both data families. A passing candidate
must next satisfy both measured timing repetitions: 80 native cells and 16 time
cells. Time includes setup, matching, transfer, normalization and acceptance,
with both full and nine-use-amortized FGR accounts. Original-history Adam supplies
last-within, first-after and best-CD-through-first-after comparisons. GT cannot
select a checkpoint. Counts do not imply mean superiority or statistical evidence.
Only passing candidates proceed to declared full paths, keeping held-EPE,
worst-pair, trajectory-AUC and runtime gates. New scenes require full-path success.
Repeated states, self-reviews and negative-result diagnostics are not acceptances.

Current experiment entry points
These require the prepared assets AND verified local reference artifacts. A code
checkout alone does not contain those datasets, traces, poses or validation records.
Do not substitute arbitrary same-key NPZs or fabricate prerequisite records.
 ndp_global_event_chain.py; global_event_chain_report.py
   Replays continuation_geometry_20261018 restored paths and108 actual events.
 ndp_normalized_mix_probe.py [--report-only]
   Checks normalized mixing at54 stopping endpoints against native_mix_20261018
   and head_preconditioner_20261018 controls; writes normalized_mix_20261018.
 ndp_normalized_timing.py [--report-only]
   Repeats the54-state screen twice and compares original-history Adam at both
   measured budgets. Times the whole restricted direction builder, including
   field construction, all inner products and native-output conversion. Checks
   all80 native/16 time cells and the earlier full-ridge speed condition. The
   previous PCG mixture is also timed separately. Diagnostic GT work is excluded.
 ndp_normalized_trajectory.py [--preflight | --report-only]
   Reuses the dense trajectory loop: the previous eight arms plus normalized
   mixing at the same cost-selected16-update budget, two executions per pair.
   Preflight reproduces the old default path. All96 previous-arm fits must match
   saved non-timing results, and the original36 full-path gates remain required.
Earlier source/reference dependencies remain explicit in each probe. Existing
verified artifacts may replace expensive regeneration; each probe checks its
reference grid rather than silently constructing a different experiment.
Do not rerun into populated output directories. Reports regenerate from saved
records; data/fixture omissions do not justify rerunning completed experiments.

Storage and publication
All runtime assets, results, private proofs, caches and temporary files stay in
this isolated lab under data. Keep each local/server lab below 1GB; the prefit
limit is 800MB. Save text records and small figures instead of model checkpoints.

published English pipeline document. Datasets, results, private proofs and caches
